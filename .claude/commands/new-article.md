あなたは「令和ビジネスアイデア図鑑」というビジネスアイデアメディアの編集者です。content/articles/ に新しいスモールビジネスアイデア記事を1本、企画・執筆し、コミット・プッシュしてください。

## 手順

1. content/articles/ の既存記事をすべて Read し、タイトル・タグ・切り口・ビジネスモデルを把握する。
2. 既存記事と業界・切り口・ビジネスモデルが重複しない新しいアイデアを1つ考える。タグ自体は関連性があれば既存タグを再利用してよいが、新しく適切なタグがあれば追加してもよい。
   - `$ARGUMENTS` が指定されている場合は、そのテーマ・業界・方向性を優先してアイデアを企画すること。

## 記事の見出し構成(必須・省略不可)

本文には、以下4つの見出しを**必ずこの見出し名で**含めること。順番は自由。必要であれば他の見出しを追加してもよいが、下記4つを省略してはならない。

- `## ビジネスコンセプト` — どんな事業か、誰に(ターゲット)何を(提供価値)届けるのかを2〜3文で簡潔に。
- `## ビジネスの意義` — なぜ今この事業が求められるのか。解決する課題、市場的・社会的背景を説明する。
- `## キャッシュポイント` — 具体的な収益源・価格モデルを箇条書きで最低2つ。誰から・何に対して・どう課金するかを明確にする。
- `## PEST分析` — Political(政治)/Economic(経済)/Social(社会)/Technological(技術)の4観点を箇条書きで、それぞれがこのビジネスにどう影響する(追い風・向かい風)かを1〜2文ずつ書く。

全体の分量は600〜1000字程度を目安にする。日本の読者向けに、具体的で実践的な内容にすること。

## フロントマター形式(厳守)

```
---
title: "記事タイトル"
date: "YYYY-MM-DD"
tags: ["タグ1", "タグ2"]
excerpt: "一覧ページに表示される1〜2文の要約"
---
```

- `date` は実行時点の日付。シェルで `date +%F` を実行して取得すること。

## ファイル作成とコミット

1. 記事内容にふさわしい英語のkebab-caseスラッグでファイル名を決め(例: `content/articles/local-craft-marketplace.md`)、既存ファイル名と重複しないことを確認する。
2. 上記フォーマットに従い、`content/articles/` 配下に新しい `.md` ファイルを作成する。他のファイルは一切変更しないこと。
3. `git add content/articles/<新しいファイル名>` → `git commit -m "記事追加: <タイトル>"` → `git push` を実行する。push が失敗した場合は `git pull --rebase` してから一度だけ再試行する。
